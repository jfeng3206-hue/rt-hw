
- what is docker, dockerfile, docker image, docker container
  - Docker: containerization platform that packages an application together with everything it needs to run into one portable unit that behaves identically on different environments
  - Dockerfile: a text file of built instructions. 
    - FROM (base image), WORKDIR, COPY, RUN, EXPOSE and ENTRYPOINT/CMD
  - Docker image: produced by building a Dockerfile. Snapshot of the app + dependencies
  - Docker container: a running instance/object of an image 

- docker vs VM
  - VM virtualizes hardware: each VM ships a full guest OS on top of a hypervisor.
  - A container virrtualizes the OS. Far lighter, faster and denser

- talk about how to use docker in real project
  - One Dockerfile per service. Add a .dockerignore, run as a non-root user, pin base-image versions, one process per container, and externalize config via env vars / the config server (never bake secrets in).
  - docker-copose for local dev
  - Image registry — CI builds the image, tags it by version/commit SHA, and pushes to a registry (Docker Hub, or AWS ECR).
  - CI/CD pipeline — build image → run tests → scan → push to registry → deploy to the cluster (rolling/blue-green).
  - Orchestration in prod — Kubernetes (EKS) or ECS schedules containers across hosts and handles scaling, health checks, rolling deploys, restarts, and service discovery. 

- check the following AWS Services and how to use them in project
  - EC2: virtual servers to host apps/containers
  - ECS: AWS container orchestrator for running dockerized microservices
  - ECR: Private Docker registry. ci pushes images here; ECS/EKS pull from here
  - RDS: Managed SQL daatabase
  - DocumentDB: Managed MongoDB-compatible
  - DynamoDB: Serverless NoSQL key-value
  - Lambda Function: Serverless functions. Event-driven/async glue, image processing, cron jobs
  - API gateway: Managed API fron door for routing, auth
  - AWS Kinesis: Real-time data streaming
  - IAM: identity and access control
  - SNS: pub/sub messaging for broadcasting one event to many consumers
  - SQS: managed message queue to decouple producers/consumers, bufferload

    **EC2 Deployment Summary**

    1. Launched an EC2 Instance
    - AMI: Ubuntu 26.04 LTS
    - Instance type: t2.micro (free tier)
    - Created key pair: springboot-demo.pem
    - Public IP: 34.222.249.137

    2. Connected via SSH (from Mac)
    - chmod 400 ~/Downloads/springboot-demo.pem
    - ssh -i ~/Downloads/springboot-demo.pem ubuntu@34.222.249.137

    3. Installed Java 17 (on EC2)
    - sudo apt update && sudo apt install -y openjdk-17-jdk

    4. Installed and Configured PostgreSQL (on EC2)
    - sudo apt install -y postgresql postgresql-contrib
    - sudo systemctl start postgresql
    - sudo systemctl enable postgresql
    - sudo -u postgres psql -c "CREATE DATABASE sms;"
    - sudo -u postgres psql -c "ALTER USER postgres WITH PASSWORD 'password';"


    5. Built the JAR (on Mac)
    - ./mvnw clean package -DskipTests

    6. Copied the JAR to EC2 (from Mac)
    - scp -i ~/Downloads/springboot-demo.pem target/demo-0.0.1-SNAPSHOTapp.jar

    7. Ran the App (on EC2)
    - java -jar app.jar --spring.datasource.url=jdbc:postgresql://localhost:5432/sms --spring.datasource.username=postgres --spring.datasource.password=password

    8. Verified Deployment
    - Confirmed port 8080 was accessible via EC2 security group
    - Tested in Postman: GET http://34.222.249.137:8080/api/students returned 200 OK
