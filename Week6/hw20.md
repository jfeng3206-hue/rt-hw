# Q&A

- TDD VS BDD VS DDD

  TDD (Test-Driven Development) focuses on writing tests before writing the implementation.
  The workflow is:
    - Write a failing test.
    - Implement just enough code to make it pass.
    - Refactor while keeping all tests green.
  For example, if I need to add a "Submit Order" feature, I'd first write unit tests for the controller, service, and repository layers, including both success and failure cases, before implementing the business logic. The implementation is driven by the tests.

  BDD (Behavior-Driven Development) focuses on business behavior rather than implementation.
  It uses scenarios written in business language like:
  Given a logged-in user, When they submit an order, Then the order should be created successfully.
  BDD improves communication between developers, QA, and product owners because everyone understands the expected behavior.

  DDD (Domain-Driven Design) is about modeling software around business domains.
  Instead of organizing code by database tables, we organize it around business concepts like:
  Order
  Customer
  Payment
  Inventory
  DDD introduces concepts like Entities, Value Objects, Aggregates, Domain Services, and Bounded Contexts to keep business logic clean and maintainable.

- what is Junit
  JUnit is the standard unit testing framework for Java.
  I mainly use JUnit 5 with Spring Boot to write unit tests.
  Each test method is annotated with @Test, and JUnit provides lifecycle annotations like: @BeforeEach @AfterEach @BeforeAll @AfterAll

  For example, when testing a controller, I use JUnit to verify that: valid requests return the expected response, invalid inputs return proper HTTP status codes, edge cases are handled correctly.
  JUnit is the foundation of our unit testing

- what is Mockito
  Mockito is a Java mocking framework used together with JUnit. Its purpose is to isolate the class we're testing by replacing its dependencies with mock objects.
  For example, when testing a controller, I don't want to call the real service or database. Instead, I mock the service like this conceptually: when employeeService.createEmployee() is called, return a predefined Employee object.

- how do you do the test for your application

  First, I write unit tests using JUnit and Mockito.
  I test each layer independently: Controller, Service, Repository (DAO), Mapper
  For each feature, I cover: happy path/invalid inputs/exception cases/edge cases

  After unit testing, I run integration tests. Integration tests verify the entire request flow: Client → Controller → Service → Repository → Database

  Finally, before deployment, depending on the project, we may also perform: regression testing, smoke testing, performance testing using JMeter, security testing

  This layered approach helps catch issues early while ensuring the complete system behaves correctly.

- what tools do you use to do code qualify analysis

  I mainly use JaCoCo and SonarQube, integrated into our Jenkins CI/CD pipeline.

  JaCoCo generates code coverage reports.

  It shows: line coverage/branch coverage/uncovered methods/uncovered classes

  This helps us understand how much of the codebase is tested.

  Then SonarQube performs static code analysis.

  It checks:
  code smells
  bugs
  security vulnerabilities
  duplicated code
  maintainability
  reliability
  test coverage

  We also configure Quality Gates.

  For example, if code coverage drops below 80%, the Jenkins pipeline automatically fails and prevents deployment.

  This ensures only high-quality code reaches production.

- Authentication vs Authorization
  Authentication answers: Who are you? It verifies a user's identity.Examples include: username/password, Google login, GitHub login, MFA

  Authorization answers:What are you allowed to do? Once the user is authenticated, the system determines their permissions.

  Authentication happens first.
  Authorization happens afterward.

- Encryption vs Hashing vs Encoding
  Encryption protects confidential data. It is reversible using a secret key.

  Hashing converts data into a fixed-length value. It is one-way and cannot be reversed. Password storage should always use a password hashing algorithm like BCrypt rather than encryption.

  Encoding simply converts data into another format. It is completely reversible. Encoding provides no security.

- how do you secure your application
  I usually secure a Spring Boot application using several layers.
  First, authentication is handled using Spring Security with JWT or OAuth2. Passwords are hashed using BCrypt, never stored in plain text. Sensitive communication uses HTTPS/TLS to encrypt data in transit.
  For authorization, I use role-based access control. I also validate all request inputs to prevent invalid or malicious data.
  For APIs, I implement: JWT expiration, refresh tokens when appropriate, CORS configuration, CSRF protection when applicable, exception handling that doesn't expose sensitive information

  Finally, our CI/CD pipeline includes SonarQube static analysis and automated testing to catch security and code quality issues before deployment.

- what is JWT
  JWT stands for JSON Web Token. It's a stateless authentication mechanism. The authentication flow is:
  User logs in with username and password.
  Server verifies the credentials.
  Server generates a signed JWT.
  Client stores the token.
  Every API request includes:
  Authorization: Bearer <JWT>
  
  The server validates the signature and expiration date before processing the request.
  A JWT consists of three parts:Header, Payload, Signature

  Since JWT is stateless, the server doesn't need to maintain session information, making it highly scalable for distributed systems.

- what is the OAuth2 

  OAuth2 is an authorization framework that allows users to grant third-party applications limited access to their resources without sharing passwords.
  A common example is: "Sign in with Google."
  Instead of giving my password to another application, Google authenticates me and issues an access token.
  The application only receives the permissions I've approved.
  OAuth2 typically involves:Resource Owner (the user), Client Application, Authorization Server, Resource Server

  In Spring Boot, OAuth2 is commonly integrated with providers like:
  Google
  GitHub
  Microsoft
  Okta
  This provides secure Single Sign-On (SSO) and delegated authorization.
