- how to increase young generation size in heap
  Use -Xmn, -XX: NewSize. Or use -Xmx and Xms to increase the whole heap size.

- how do you handle exception in java
  - Checked exceptions must be handled using throws keyword and try-catch-finally block, where finally always runs
  - Unchecked exceptions can be handled using extending RunTimeException class and customized Exception class. If in SpringBoot, can be handled via global exception handler using @@RestControllerAdvice

what annotations we use to configure customized actuator
  - Default endpoints: add the actuator dependency and enable endpoints in config
  - Custom endpoints: @Endpoint on the class then: @ReadOperation for GET, @WriteOperation for POST, @DeleteOperation for DELETE

can abstract class have no abstract method
  Yes. 

how can you use optional
  Wrapper class in Java 8 to avoid null pointer exception.
  Optional.of(value) to wrap a non-null value and throw if null, ofNullable() allows null value and return empty Optional instead. orElse provides a default value when null, and orElseThrow

What is functional interface?
  Java 8 new feature. An interface with exactly 1 abstract method. Used through the StreamAPI, implemented with lambda expressions. 
  4 Types: Consumer (1 input, no output), Supplier(no input, 1 output), Predicate(1 input, boolean output), Function(1 input, 1 output)

Why do you use post, instead of put
  POST is for insertion, creating new data, not idempotent.
  PUT is for updating. idempotent.

what is webflux? Have you used it in your project
  Non-blocking asynchronous Spring Framework based on Reactive lab. Stream requests through a data pipeline instead of Tomcat's thread-per-request model.
  Mono wraps a single object. Flux wraps multiple and returned as a stream the caller subscribes to.

What is hashmap?
  Implementation of map interface. key-value structure, unique keys. o(1) get/put. 
  Stores by computing the key's hashcode and maps to a bucket. if same hash, use equal to check the hash collision. buckt is resolved with a linkedlist, after java 8, converted to a red-black tree. must override hashchode and equal so keys compare by value, not by reference.

what is enable auto configuration
  One of the three annotations inside @SpringBootApplication.
  Allows SpringBoot to autoconfigure by:
  1. class scanning using componentscan
  2. dependency checking in pom.xml file
  3. conditional bean injection: @ConditionalOnMissingBean (create only if absent), @ConditionalOnClass (create only if a package is on the classpath).

### Q&A
- sql vs no sql database

  - SQL stores tabular data with rows and columns. SQL database has structured and fixed schema, enables filtering and sorting with query language. SQL database also support join across tables. It is preferred when your data is well-defined and relationships matter. SQL gives stronger consistency and powerful joins but is harder to scale horizontally.

  - NoSQL supports a flexible schema where different records can have different fields. It includes document stores such as MongoDB, key-value stores (Redis), columnar, graph, and full-text search(Elasticsearch). It is preferred when you need to scale out, or data is unstructured, or when you need a specialized access pattern, like caching, search, relationships. NoSQL gives flexibility and easy horizontal scaling, but gives up on strict consistency and joining.

- what is database normalization

  Normalization means designing the tables so no repetitive data in multiple places. Normalization reduces duplication but adds joins, so sometimes denormalizing helps speed up reads under heavy traffic.

  1NF - every cell holds a single value (no list into one column)
  2NF - every column depends on the whole primary key
  3NF - no column depends on another non-key column (don't store both birth date and age, since age is derivable)

  In practice, usually stop at 3NF because normalization is a trade-off. 

- vertical scaling vs horizontal

  - Vertical scaling: 1 server with more power(CPU, RAM, faster disk etc.) Pros: simple. Cons: hard ceiling exists/single point of failure

  - Horizontal sacling: adding more servers and spreading load. Need to have stateless app and handle load balancing and data consistency. Pros: more fault-tolerant/no hard ceiling. Cons: more complex. 

- what is ACID

  ACID is 4 guarantees that make database transaction trustworthy, mostly in SQL databases. A transaction is a group of operations that should succeed or fail as a single unit.

    - Atomicity: all-or-nothing. Either every step happens or none does; if the credit fails, the debit rolls back, so money never disappears halfway.

    - Consistency: the database moves from one valid state to another, with all constraints holding before and after.

    - Isolation: concurrent transactions don't step on each other. Running 2 at once gives the same result as running them one after another

    - Durability: once committed, it is permanent. Even if the server crashes a second later, the data survives because it's written to disk.

- what is CAP

  CAP is about distributed systems and you can only fully guarantee 2 of three at once.

  - Consistency: every read sees the most recent write; all nodes show the same data.
  - Availability: every request gets a response, even if some nodes are struggling
  - Partition tolerance: the system keeps working even when the network between nodes breaks. 

  Example: a single-node sql is CA; MongoDB leans CP; Cassandra and DynamoDB lean AP.
